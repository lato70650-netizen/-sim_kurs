## Публикация и проверки

Публикация облачной среды и публикация сайта на GitHub Pages — разные операции. Для сайта изменения коммитят и отправляют в main. Успешный push не доказывает завершение Pages deployment; статус проверяют в Actions. API GitHub и публичный домен Pages могут быть недоступны из облачной среды; Git через штатный прокси работает. Не запрашивать токены, если существующий Git-доступ пригоден. При изменениях CSS/JS обновлять версии их URL в index.html, чтобы избежать старого кеша.

## Авторизация по email

Добавлены «Войти», самостоятельная регистрация и «Выйти» через Supabase Auth, проект `sim_kurs`. В шапке отображается email вошедшего пользователя, сессия сохраняется при обновлении страницы. Форма поддерживает показ пароля, ошибки, загрузку, клавиатуру и мобильный экран. Подтверждение email отключено в Supabase, проверено через `/auth/v1/settings`.

Реальный браузерный сценарий пройден: регистрация → обновление страницы → выход → неверный пароль → повторный вход → выход. Тестовый аккаунт: `sim-qa-a6f253bbe9d8@example.com`; после проверки сессия завершена. Пароль не сохраняется в репозитории.

## Минимальная длина пароля

По просьбе пользователя минимум в форме регистрации снижен до 6 символов. Владелец изменил Minimum password length в Supabase Email provider на 6. Проверка на опубликованном сайте пройдена: регистрация с паролем ровно из 6 символов, сохранение сессии, выход и повторный вход.
